# RA Workspace 用户路径体验评估与页面升级建议（蛋白质知识库 → 药物分子对接）

## 1. 评估范围与当前路径

本评估基于当前项目代码中的两个核心页面：

1. **蛋白质知识库**：`Home/Targets`
2. **药物分子对接**：`Job/New`

模拟用户路径：进入 RA workspace → 点击 **Protein Database** → 浏览/筛选目标蛋白 → 点击 **Continue to Docking** → 进入 **Docking workspace** 创建任务。

---

## 2. 模拟用户“使用感觉”（按点击顺序）

### Step A：进入蛋白质知识库（Protein Database）

**正向感受**
- 页面视觉层级清晰（标题、统计、检索、卡片/表格切换），信息密度对科研用户友好。
- 支持搜索、标签筛选、卡片/表格双视图与分页大小切换，能覆盖“快速浏览 + 精确比对”两种使用模式。
- 提供“Continue to Docking”明确引导下一步，不会让用户迷路。

**负向感受（主要摩擦）**
- `Default number of records shown per page` 是固定文案 `20`，与实际用户切换到 50 条后会产生“文案与状态不一致”的心理落差。
- 标签较多时仅横向铺开，缺少“更多/收起”与“已选筛选条件胶囊”，用户会感到筛选状态不够可见。
- 搜索框支持多字段，但没有“搜索语法提示”和“无结果修复建议”（例如建议改查 Gene Symbol / UniProt）。
- 打开图片预览后，与“查看详情/加入对接”之间仍是分离动作；科研用户在高频判断时会觉得点击链路偏长。

### Step B：进入药物分子对接（Docking workspace）

**正向感受**
- 页面把“提交表单”和“流程说明”并排，首次用户可快速理解流程。
- 保留“Browse Protein Database / View All Jobs”回退路径，降低迷航风险。

**负向感受（主要摩擦）**
- 页面文案存在**规则冲突**：顶部写“Up to N ligands”，而右侧规则又写“仅可提交一个药物结构”，会让用户对系统能力不确定。
- Create Job 的前置校验提示不够“就地化”：用户通常在点击后才知道缺字段，缺少逐项即时反馈（名称重复、SMILES 重复、格式错误）。
- 从知识库带入对接页时，缺少“我刚才选中了哪个蛋白/标签”的上下文记忆，任务创建页与上一步断层。
- 缺少“预计排队时间/并发负载感知”信息，用户点击创建后可能焦虑等待时长。

---

## 3. 页面升级建议（按优先级）

## P0（建议优先做，投入小、收益高）

### 3.1 统一规则文案与约束呈现
- 在 Docking 页将“可提交分子数”统一为同一来源（`maxLigands`），所有提示位置共用同一文案模板。
- 删除或改写“只能提交一个分子”的冲突文案，避免用户误判。

**预期效果**：减少首屏理解成本，降低表单放弃率。

### 3.2 强化表单即时校验（字段级）
- Job Name：输入框 blur 时即时校验非空、长度与非法字符。
- Ligand Name/SMILES：在每个分子块内显示即时错误提示，不等到最终提交。
- 提交按钮在校验未通过时置灰，并显示“还缺 2 项信息”式提示。

**预期效果**：减少“提交后报错再回填”的往返操作。

### 3.3 在知识库增加“无结果恢复”设计
- 搜索无结果时显示：
  - 你可以尝试：蛋白名 / Gene Symbol / UniProt ID
  - 一键清空筛选按钮
  - 最近使用标签（可选）

**预期效果**：减少用户误以为“数据库无数据”的负面感知。

---

## P1（建议第二阶段，提升跨页面连续体验）

### 3.4 做“带上下文进入 Docking”的连续体验
- 在 Protein Database 的卡片/表格增加“以该蛋白开始对接”入口。
- 跳转到 Docking 时携带参数（proteinId / tagId / query），Docking 页顶部显示“当前来自：XXX 蛋白（可清除）”。
- 若当前后端任务模型确实是“对 domain 全量目标跑任务”，也应明确文案：
  - “你当前在 RA 域创建任务（非单蛋白限定）”
  - “来自蛋白 XXX 的上下文仅用于辅助命名与回看”

**预期效果**：强化“我从哪里来、我现在在做什么”的认知连续性。

### 3.5 让统计信息“动态反映当前状态”
- 知识库顶部统计卡中“每页记录数”应绑定当前 page size（20/50）。
- “visible records”同时显示筛选前总数与筛选后数量（如 `18 / 236`）。

**预期效果**：提升可解释性，减少用户对列表变化的困惑。

### 3.6 预览弹窗加入快捷动作
- 在蛋白预览弹窗里增加：
  - 查看详情
  - 继续到 Docking（保留上下文）

**预期效果**：把“看图 → 决策 → 行动”压缩为同一交互闭环。

---

## P2（中期优化，偏产品化能力）

### 3.7 任务创建后的“可预期等待”体验
- 创建成功后 toast 显示：队列位置、预计开始时间（或“当前排队任务数”）。
- 在 All Jobs 列表提供“仅看我的最近任务”快捷筛选。

### 3.8 提供“模板化创建任务”
- 基于最近一次成功任务，支持“复制任务并替换分子”。
- 常用输入（job name 前缀、私有设置）可记忆。

### 3.9 新手引导与专家模式切换
- 新手模式：显示步骤提示与字段解释。
- 专家模式：默认折叠说明区，保留高密度表单。

---

## 4. 建议的落地顺序（两周节奏示例）

### 第 1 周（P0）
1. 统一 Docking 文案规则（消除冲突）。
2. 增加表单字段级即时校验与按钮可用态。
3. 增加知识库无结果恢复组件。

### 第 2 周（P1）
1. 打通知识库 → Docking 的上下文参数。
2. 统计卡动态化（页大小、筛选前后数量）。
3. 预览弹窗增加快捷动作。

---

## 5. 验收指标（建议）

- 蛋白质知识库 → Docking 页面跳转转化率。
- Docking 页面表单首次提交成功率。
- Create Job 平均完成时长。
- 无结果搜索后的恢复率（清空筛选后继续浏览比例）。
- 创建任务后 5 分钟内离开率（衡量等待焦虑）。

---

## 6. 结论

当前 RA Workspace 的信息架构已具备“可浏览、可筛选、可提交任务”的主流程基础；核心优化机会不在“重做页面”，而在：

1. **规则一致性**（避免冲突文案），
2. **跨页面上下文连续性**（从蛋白到任务的心智不断裂），
3. **即时反馈与可预期性**（减少提交焦虑）。

优先做 P0 + P1，可在不改动底层计算逻辑的前提下，明显提升首次用户与高频用户的操作顺滑度。
